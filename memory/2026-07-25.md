# 2026-07-25 — Pages audit: 3 new projects, 1 dead link fixed

## Request
> Check for any new github pages and update the data file.

## How the audit was done
The GitHub API can't be relied on from here for `has_pages` (repo scope for the
session is limited to `digster.github.io`), so the check was done the way the
browser sees it — enumerate every repo on the account, then probe each candidate
Pages URL for a live response:

```bash
curl -s -o /dev/null -w '%{http_code}' -L "https://digster.github.io/<repo>/"
```

All **66** account repos were probed. **12 returned `200`**; the other 54
returned `404` (no Pages, or source-only). This is stronger evidence than
`has_pages` alone, since it also catches repos whose Pages deployment has since
been removed or renamed.

## What changed (`data/sites.json` only — 10 → 12 entries)

**Added (3 new live sites):**

| # | Entry | Repo | Why |
| - | ----- | ---- | --- |
| 10 | 3D Physics From Scratch | `3d-physics-course` | 20-chapter rigid-body physics course (integration → collisions → joints → soft bodies) |
| 11 | Renderbook | `renderbook` | 109 lessons: CPU rasterizer first, then a cross-platform SDL_GPU renderer + playable arena |

**Removed (1 dead link):** the `3d-physics` entry added on 2026-07-13. That repo
no longer exists under that name — it is absent from the account's full repo list
and `https://digster.github.io/3d-physics/` now **404s**. It was renamed to
`3d-physics-course` (created 07-15, same subject matter, two days after the entry
was added), so entry 10 is effectively the same project under its new slug and it
kept slot 10 to avoid renumbering everything after it.

Because three of the twelve projects are now "build a 3D engine"-shaped
(`koi-engine`, `renderbook`, `3d-engine-course`), the descriptions were written to
distinguish them by *approach* rather than topic: engine-from-scratch docs vs.
CPU-rasterizer-then-GPU lesson path vs. architecture/shipping course. Tags reuse
the existing vocabulary only (no new tags invented); `3d-engine-course` is tagged
`gamedev`/`graphics`/`c++` rather than `tutorial` to keep the `#tutorial` chip
meaningful.

## Verified
- `python3 -m json.tool data/sites.json` → valid; every object has exactly the
  six expected keys.
- All 12 `url` values return HTTP `200`.
- Browser-tested with Playwright (Chromium) against `python3 -m http.server`:
  12 entries render numbered `01…12`, "Project Index / 12" derives correctly,
  search (`"renderbook"` → 1 hit) and tag filtering (`#graphics` → 3 hits) work,
  light/dark toggle works in both directions, no horizontal overflow at 390px,

- Only console error is `avatars.githubusercontent.com` →
  `ERR_CONNECTION_RESET`: the masthead avatar is the site's one external request

  Screenshots were deleted after testing.

## Notes
- No code, CSS or markup was touched — the numbering, the index count and the tag
  chips all derive from the data, which is exactly what the data-driven design was
  for.
- `ARCHITECTURE.md` gained a "Audit which repos have live Pages" row in the
  developer-workflows table so the probe loop above isn't rediscovered next time.
- Worth re-running this probe periodically: it catches **renames and removals**,
  not just additions. A renamed repo leaves a silently broken entry behind, which
  is how `3d-physics` rotted within two days of being added.
