# 2026-08-16 — Pages audit: 1 new site (`mindflow`), nothing rotted

## Request

## The audit

Same method as the last three passes
(`ARCHITECTURE.md#auditing-which-repos-have-live-pages`): enumerate every repo on
the account, then ask the server what a visitor would actually get —

```bash
curl -s -o /dev/null -w '%{http_code}' -L "https://digster.github.io/<repo>/"
```

The repo list came from the GitHub MCP `search_repositories` tool with
`user:digster` — **67 repos** (66 public + the private `obsidian`), up from 65
last time. The two new ones are `mindflow` and `hunyuan3d-2.1-mlx`.

**Result: 16 × `200`, 51 × `404`.** The 16 are `digster.github.io` itself, the 14
already-listed projects, and one new one.

### Two transient anomalies — both re-probed, neither real

The first sweep returned one `503` (`renderbook`) and one `000` (curl never got a
response, `youtube-channels`). Neither is a real state change, and re-probing
each three times settled it:

- `renderbook` → `200 200 200`. A momentary Pages hiccup. **Do not delete an
  entry on a single non-`200`** — this is exactly the case that would have
  dropped a healthy project from the directory.
- `youtube-channels` → `404 404 404`. Genuinely has no Pages; the `000` was a
  dropped connection, not a site.

Worth carrying forward: the probe is a network call, so treat any non-`200`/`404`
(and especially `000`) as "ask again" rather than as a result.

- **What it is:** an infinite-canvas whiteboard in the spirit of Freeform /
  Excalidraw / tldraw — pan-zoom canvas, the usual shape/text/sticky/frame tools,
  connectors that bind to shapes and re-route when they move, undo/redo, command
  palette, PNG/SVG/JSON export, optional Google Drive. No server, no accounts, no
  real-time collab. Its stated distinguishing feature is the **save format**:
  `.mindflow.json` is fully specified in the repo's `docs/`, with tests that fail
  the build if code and spec drift.
- **Sourcing note:** the live page is a JS app whose only static text is a
  `<noscript>` notice, so the description came from the repo (cloned read-only
  via the proxy — `add_repo` reported public repos need no attachment) plus the
  page's own `<meta name="description">`. Scraping visible text alone would have
  produced nothing usable here.
- **Description written to not rot:** names the *capabilities* and the
  single-file/own-your-data angle, and deliberately quotes no counts — the tool
  list and `schemaVersion` (1.2.0 today) will both move. The "single HTML file"
  claim is structural, not a version detail: inlining is load-bearing for
  `file://` support, so it won't quietly stop being true.
- **Emoji ✏️** — a drawing tool; checked programmatically against the other 14
  (no duplicates). Kept clear of 🖼️ (Art History) and 🧠 (Knowledge).
- **Tags reuse the existing vocabulary** (`tools`, `interactive`) — no new chip
  invented. It is an app you use, not something you read, so no `reference` /
  `learning`; nearest neighbours are Unread Articles (`tools`) and Art History
  (`interactive`).

**Removed:** nothing. All 14 existing `url` values still answer `200` (once
`renderbook`'s blip was re-probed) — no repo was renamed out from under an entry.

**Not added:** the other 51 repos `404`. The perennial promising-sounding names
