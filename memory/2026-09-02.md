# 2026-09-02 — The tag palette, rebuilt around the chip treatment

## Request

Fourth pass at the same problem (see 2026-08-29 and 2026-08-31). No data

## The reframe

The previous three passes all tried to spread *hues* further apart while the
chip stayed the same object: a faint wash with coloured text on it. That
treatment is the real ceiling. Colour-as-ink has to clear 4.5:1 against white,
which confines the entire palette to a thin, muted shell of the gamut — and
inside that shell sRGB has no saturated yellow, green or teal to offer, so a
third of the wheel converges toward grey however far apart the hue angles are.
Two chips also only differ across the few hundred pixels of their letterforms.

So the chip became a **filled block with the label reversed out of it**. The
only constraint left is that one of the page's two inks reads on the fill,
which opens the deep, mid and pale ends of the gamut at once and multiplies
the area carrying the colour.

## The palette is now solved, not spaced

`buildTagColors()` (in `app.js`) takes the sorted vocabulary and:

1. **Builds candidates** — a 10 × 72 grid of lightness × hue, each at the most
   chroma sRGB holds there (capped at 0.15, which is taste rather than gamut:
   past it the set goes neon), at full strength and at 72%. Candidates are
   dropped unless a label reaches AA on them and the block is visibly not the
   page.
2. **Solves max-min** — farthest-point seeding, then swap refinement: move each
   colour, in turn, to wherever it buys the largest *minimum* gap; stop when a
   pass changes nothing.
3. **Orders the result apart** — `spreadOrder()` puts the most distant colour
   next in line each time, because the vocabulary is alphabetical and a set
   laid out in hue order reads as one gradient however far apart it measures.
4. **Derives the dark twin** — same hue, same share of the local chroma
   ceiling, lightness mapped 0.40–0.75 → 0.46–0.78, so a topic stays itself
   across the theme flip. `paintTag()` writes both themes onto the chip and
   CSS aliases one pair, so the toggle never repaints anything.

Colours are computed in JS and emitted as **hex**, never as CSS `oklch()`.
That kills the portability trap recorded on 2026-08-31 for good: Chromium
clips out-of-gamut OKLCH per channel while spec-following engines reduce
chroma, so an `oklch()` declaration is not necessarily the same colour twice.
Mapping into sRGB once, here, makes it one colour everywhere.

| | before | after |
| --- | --- | --- |
| closest pair, light (Oklab) | 0.077 | **0.157** |
| closest pair, dark (Oklab) | 0.107 | **0.159** |
| worst label contrast | 5.04:1 / 5.22:1 | **4.83:1 / 4.64:1** |
| colour-bearing area | letterforms + 12% wash | the whole chip |

The worst label figure went *down* slightly and that is the deliberate trade:
it is the constraint being spent to buy the distance, and it is still AA.

## Two things that had to change with it

- **The selected chip rings instead of inverting.** Inversion has nothing left
  to invert into once the fill is solid, so `[aria-pressed="true"]` draws a
  ring in the page's ink with a gap in the page's paper. `All` still inverts
  (no topic, no colour) and is excluded from the ring *by name* — the ring
  rule sits later in the file and would otherwise win on equal specificity.
- **The count inside a chip stays at full ink**, at regular weight rather than
  bold. Fading it, as before, would drop small text under AA on its own fill;
  the weight difference carries the hierarchy instead.

## Notes

- **Performance mattered here and `Math.hypot` was the whole cost.** The first
  working version took 71 ms to solve 13 colours; comparing *squared* distances
  in the search loops (the searches only ever compare) took it to 16 ms, and
  ~32 ms at 26 tags. The scaling is worth knowing before the vocabulary grows.
- **A sign error cost one round of measurement.** `darkTwin()` nudges lightness
  when the mapped value lands in the crossover where neither ink reaches AA,
  and the first version stepped *toward* the crossover — contrast with the
  light ink grows as the fill darkens, not as it lightens. It showed up as one
  dark chip at 4.22:1.
- The dark band was picked by sweeping it, not guessed: 0.46–0.78 measured
  best. Taking it to 0.86 collapsed the closest pair to 0.095, because the
  chroma ceiling falls away at high lightness and the pale end turns to pastel.
- `LEARNINGS.md`, `ARCHITECTURE.md` and `README.md` all rewritten around the
  new scheme — the old entries described hue spacing, an alternating lightness
  band and `--tag-hue`/`--tag-l`/`--tag-c`, none of which exist any more.
